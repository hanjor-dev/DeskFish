# DeskFish 架构设计

## 1. 目标与约束

架构必须支持：桌面常驻、离线推进、可恢复存档、可测试的养成规则、可替换的鱼只表现和未来排行榜接入。

当前原型中的 `TankPrototype`、`FishAgent` 和 `TankInteraction` 保留为技术验证样本；正式功能不得继续把领域规则绑定在原型 MonoBehaviour 中。

## 2. 分层与目录

```text
Assets/DeskFish/
  Runtime/
    Domain/          鱼只、鱼种、鱼缸、成长、照料、资源、积分、领域事件
    Application/     用例、命令、时间结算、存档协调
    Presentation/    Unity 场景、鱼只表现、动画、UI、输入映射
    Infrastructure/ 本地文件、日志、配置、未来排行榜客户端
    Platform/        Windows 窗口、穿透、快捷键、托盘、位置恢复
  Editor/
  Tests/
```

依赖方向为 `Presentation/Platform → Application → Domain`。`Infrastructure` 通过接口被 `Application` 使用；`Domain` 不依赖 Unity、Windows API 或文件系统。

## 3. 领域模型

核心实体和值对象：

- `Tank`: 用户鱼缸及鱼只集合。
- `Fish`: 独立鱼只个体，引用 `SpeciesId` 并维护成长、照料和状态。
- `FishSpecies`: 鱼种配置，不保存个体运行时状态。
- `ResourceWallet`: 养成资源余额与变更。
- `ScoreLedger`: 本地积分累计、每日限额和去重摘要。
- `UserProfile`: 匿名身份、可选昵称和用户设置。
- `SimulationClock`: 领域使用的真实时间和最后结算时间。

领域事件至少包括：`FishFed`、`FishClicked`、`AttractionStarted`、`AttractionUpdated`、`AttractionEnded`、`FishGrowthStageChanged`、`ResourceGranted`、`ScoreGranted`。

鱼群不是持久化实体。鱼只独立决策，鱼群行为通过邻近关系和短时吸引影响实现。

## 4. 应用层与数据流

输入来源统一转换为命令，例如 `ClickWater`、`SelectFish`、`StartAttraction`、`UpdateAttraction`、`EndAttraction`、`FeedFish`、`ToggleInteractionMode`。

用例服务接收命令，校验规则，修改领域状态并发布领域事件。表现层订阅领域结果，负责移动、动画、特效和 UI 展示，不直接修改成长、资源或积分。

时间流程：

1. 启动时读取并校验存档；
2. 领域时钟计算经过时间；
3. 按 24 小时上限裁剪离线时间；
4. 时间结算服务一次性更新成长、资源、观赏时长和积分；
5. 发布结算摘要供 UI 展示；
6. 自动保存新快照。

运行期间，领域规则按分钟级或事件触发结算；游动、动画和交互反馈按 Unity 帧运行。

## 5. 配置与存档

鱼种、成长阶段、食物份量、资源产出、解锁价格和性能档配置采用 ScriptableObject 或等价的版本化配置；鱼只个体状态独立存档。

存档写入流程：生成完整快照 → 写入临时文件 → 校验 schema、校验和与关键范围 → 替换主文件 → 保留上一份备份。加载失败时依次尝试备份，并输出本地诊断日志。

存档包含 schema 版本。迁移器只负责受支持版本到当前版本的确定性转换；重置和导入通过应用层命令执行，不允许 UI 直接写文件。

## 6. 表现与性能

表现层将领域状态/事件解释为鱼只移动、转向、躲避、聚拢、散开、成长外观和 UI 反馈。领域层不保存每帧鼠标位置；长按吸引按固定频率聚合更新。

性能档为低/中/高，建议容量分别为 10/20/40 条鱼。超出建议容量时依次降低粒子和环境效果、鱼群行为更新频率、鱼只动画质量，不自动删除鱼只。

首次启动执行短时可跳过的基准测试，用户可以手动覆盖结果。目标是普通档 20 条鱼连续运行 8 小时无明显内存增长或行为退化。

## 7. Windows 适配

平台适配层封装透明、无边框、置顶、鼠标穿透、快捷键、托盘和窗口位置恢复。Unity 输入只处理已被平台层允许的交互状态。

平台能力不可用时，核心鱼缸和本地养成仍应运行；能力失败写入日志并在设置中提供可理解的状态反馈。

## 8. 排行榜边界

MVP 的本地 `ScoreLedger` 与模拟网页通过导出/读取的展示数据连接，不建立真实账号或服务端依赖。

未来联网时，客户端提交可验证事件，服务端计算总分和排名。客户端保留离线体验，并通过同步状态展示待提交、已提交和失败重试结果。

## 9. 测试策略

- Domain 单元测试：成长、离线结算、时间回拨、喂食过量、资源、积分限额、去重和迁移。
- Application 测试：命令、事件、存档协调和失败回退。
- Unity PlayMode 测试：输入、鱼只表现、信息卡、长按吸引和窗口状态协作。
- Windows 包验收：透明窗口、穿透切换、托盘、DPI、多显示器和 8 小时稳定性。

领域测试注入时钟、随机源和规则配置，使用固定种子和固定时间保证确定性。

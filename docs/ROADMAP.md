# DeskFish 实施路线

## 阶段 0：基线固化（当前）

- 持久化产品共识、MVP 边界和关键技术决策。
- 完成产品需求规格、架构分层、领域术语和存档/排行榜边界定义。
- 保留技术验证中的可运行场景，避免在美术迭代时失去回归样本。

## 阶段 1：视觉与桌面窗口纵切片

- 将方块占位鱼替换为可扩展的鱼只表现资源。
- 增加摆尾、转向、速度变化、停留和轻微随机行为。
- 增加水体渐变、光照/焦散、植物摆动和气泡层次。
- 完成无边框、透明、置顶、鼠标穿透与交互切换的 Windows 独立包验证。
- 建立 `Domain`、`Application`、`Presentation`、`Platform` 和 `Infrastructure` 的最小骨架。
- 建立低/中/高性能档与 10/20/40 条鱼的基准测试。
- 目标：用户可以把鱼缸放在桌面上持续运行，并愿意长时间观看。

## 阶段 2：最小养鱼闭环

- 定义鱼只状态：生命状态、成长状态、需求和可观察反馈。
- 加入喂食、互动、资源和成长的确定性领域规则。
- 加入本地存档与启动恢复。
- 实现 24 小时离线结算上限、时间回拨保护、原子保存、备份回退和存档迁移。

## 阶段 3：积分与排行榜闭环

- 冻结积分来源、结算时机和反作弊边界。
- 设计客户端与排行榜服务的数据边界。
- 实现网页排行榜的最小读取页面。
- 实现客户端提交或同步积分的最小链路，并保留离线失败时的本地体验。

## 阶段 4：打磨与发布验证

- 性能、内存、窗口兼容性和多显示器验证。
- 视觉一致性、动效节奏、音效与可访问性打磨。
- 打包、安装、升级和日志诊断流程。

## 下一步唯一优先级

先完成“视觉与桌面窗口纵切片”，同时建立最小领域骨架，不展开排行榜后端。它能最快验证 DeskFish 是否真正具备桌面陪伴产品的核心质感，并为后续养鱼系统提供稳定承载层。

# Domain documentation

This repository uses a single-context layout:

- `CONTEXT.md` is the glossary and domain language source of truth.
- `docs/adr/` contains accepted architectural decisions.
- `docs/PRODUCT-REQUIREMENTS.md` contains product requirements.
- `docs/ARCHITECTURE.md` contains implementation architecture.
- Domain terms should be resolved in `CONTEXT.md` before adding implementation details.
- ADRs should be added only for hard-to-reverse, surprising decisions with meaningful trade-offs.
